# Morning Briefing

매일 확인하던 글로벌 매크로 지표, 국내 투자자별 수급, 신용잔고 추이를 자동으로 수집해 텔레그램으로 받아보고, 주요 지표는 노션에도 1시간마다 갱신해 두는 개인용 시장 브리핑 시스템입니다.

## 만든 이유

업무 특성상 매일 금리, 환율, 선물, 원자재 가격과 국내 수급 흐름을 확인해야 했지만 데이터가 여러 사이트에 흩어져 있어 매번 수작업으로 찾아봐야 했습니다. 반복되는 확인 과정을 줄이고 정해진 시간에 필요한 정보만 한 번에 받아보기 위해 직접 구축했습니다. 이후 장중에도 최신 값을 볼 수 있도록 노션 대시보드용 데이터를 1시간마다 갱신하는 기능을 더했습니다.

## 구성

### 텔레그램 브리핑

| 브리핑 | 발송 시간 (KST, 주말·공휴일 제외) | 내용 | 데이터 출처 |
|---|---|---|---|
| 글로벌 매크로 대시보드 | 07:00 | 오늘의 핵심 이슈(글로벌 매체 헤드라인 3건 + AI 한 줄 설명), 향후 2주 미국 주요 일정(CPI, 고용, PCE, GDP, ISM, FOMC 등, 중요도 표시), 미국채 금리, 달러인덱스, 원/달러, VIX, 주요 선물, 코스피/코스닥, 유가, 금, 구리, 가상자산 등락 및 AI 시장 코멘트 | yfinance, 네이버 금융, Reuters·Bloomberg·WSJ·FT·CNBC RSS, FRED, BEA, 연준, Gemini 2.5 Flash |
| 신용잔고 추이 | 16:30 | 유가증권시장 및 코스닥 신용거래융자 잔고 6개월 추이 차트 | 금융투자협회 FreeSIS |
| 투자자별 누적 순매수 | 19:00 | 개인, 기관, 외국인 누적 순매수 추이 (롤링 24개월) 차트 | KRX (pykrx) |

### 노션 연동 (매일 24시간, 1시간마다)

| 작업 | 실행 시각 | 내용 | 저장 위치 |
|---|---|---|---|
| 시장 지표 | 매시 47분 (+ 07:00 브리핑 때) | 대시보드와 같은 26개 지표의 현재값, 전일 대비 등락(금리는 bp), 최근 1개월 종가 추이. AI 시장 코멘트는 07:00 브리핑 때만 갱신 | 노션 「📈 시장 지표」 DB |
| 매크로 모니터 | 매시 17분 | 주식(국내·미국·일본·중국), 미국 금리, 환율, 원자재·위험지표(VIX, 비트코인) 20개 지표의 현재값, 기간별 변화(1일·1주·1개월·연초 이후·1년), 52주 범위, 1년 일봉 | 노션 「🌐 매크로 모니터」 DB |

## 동작 구조

```
GitHub Actions (스케줄 실행)
  ├ 텔레그램 브리핑 (평일)
  │   > 데이터 수집 (yfinance, 네이버 금융, KOFIA, KRX)
  │   > 가공 (등락률 계산, 이상 변동 탐지, 차트 생성)
  │   > AI 코멘트 생성 (Gemini 2.5 Flash, 매크로 대시보드만 해당)
  │   > 텔레그램 전송  (+ 매크로 대시보드는 지표와 AI 코멘트를 노션에도 저장)
  └ 노션 갱신 (매일, 1시간마다)
      > 지표 수집 (시장 지표: yfinance·네이버 금융 / 매크로 모니터: Yahoo Finance 차트 API)
      > 노션 DB에 지표별로 덮어쓰기 (Notion API)
```

- 별도 서버 없이 GitHub Actions 스케줄러로 자동 실행됩니다
- 설날, 추석 같은 음력 명절과 대체공휴일, 연말 휴장일에는 텔레그램을 발송하지 않습니다 (`kr_calendar.py`)
- 투자자별 수급 데이터는 CSV로 누적 저장해 매일 신규 거래일분만 추가 수집합니다
- 지표별로 임계치를 설정해 평소보다 크게 움직인 지표를 따로 표시합니다
- 시장 지표의 이름과 순서는 아침 브리핑(`dashboard.py`)과 1시간 갱신(`market_hourly.py`)이 똑같이 맞춰져 있습니다
- 모든 워크플로는 Actions 화면에서 수동 실행(Run workflow)할 수 있습니다. 대시보드는 "주말·공휴일에도 발송"을 체크하면 휴일에도 테스트 발송됩니다

## 설정

GitHub 저장소 Settings > Secrets and variables > Actions 에 아래 값을 등록합니다.

| 이름 | 쓰는 곳 | 비고 |
|---|---|---|
| `TELEGRAM_TOKEN` | 텔레그램 브리핑 3종 | 텔레그램 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 텔레그램 브리핑 3종 | 받을 대화방 ID |
| `GEMINI_API_KEY` | 매크로 대시보드 | AI 시장 코멘트, 헤드라인 한 줄 설명 |
| `FRED_API_KEY` | 매크로 대시보드 | 선택. 없으면 주요 일정은 BEA, ISM, FOMC만 표시 |
| `KRX_ID`, `KRX_PW` | 투자자별 수급 | KRX 데이터 조회 로그인 |
| `NOTION_TOKEN` | 노션 연동 2종, 매크로 대시보드 | 노션 내부 통합 토큰. 대상 DB가 있는 페이지에 통합을 연결해야 함. 대시보드는 없으면 노션 저장만 건너뜀 |

로컬에서 돌려볼 때는 같은 이름의 환경 변수를 지정한 뒤 실행합니다.

```bash
pip install -r requirements.txt
python dashboard.py        # 휴일에도 보내려면 FORCE_SEND=1
python market_hourly.py
```

## 문제 해결 과정

**스케줄 시간 오류**
GitHub Actions의 cron은 UTC 기준으로 동작해 처음에는 브리핑이 한국 시간과 어긋나게 발송됐습니다. 발송 시간을 UTC로 환산해 재설정하고, 코드 내부에서도 한국 영업일 여부를 KST 기준으로 판단하도록 수정했습니다.

**정각 실행 지연**
GitHub Actions는 정각에 작업이 몰려 예약 실행이 늦어지는 경우가 많았습니다. 1시간마다 도는 노션 갱신은 17분, 47분처럼 정각을 피하고 서로 겹치지 않는 시각에 실행되도록 나눴습니다.

**KRX 데이터 수집 차단**
KRX 정책 변경으로 로그인 인증 없이는 수급 데이터 조회가 되지 않는 문제가 발생했습니다. 계정 정보를 Secrets에 등록해 인증을 처리하고, 장기 구간은 180일 단위로 나눠 요청 간격을 두고 실패 시 재시도하도록 구성했습니다.

**신용잔고 페이지 구조**
금융투자협회 통계 페이지는 화면이 스크립트로 그려지는 구조라 일반적인 방식으로는 숫자를 가져올 수 없었습니다. Playwright로 브라우저를 실제로 띄워 엑셀 다운로드 버튼을 클릭하는 방식으로 데이터를 확보했습니다.

**텔레그램 메시지 길이 제한**
AI 코멘트가 길어지면 텔레그램 메시지 한도(4,096자)를 넘어 전송이 실패했습니다. 메시지를 일정 길이로 분할해 순차 전송하도록 수정했습니다.

**AI 코멘트 오류 덮어쓰기 방지**
Gemini 호출이 실패하면 오류 문구가 코멘트 자리에 들어가는데, 이것이 노션에 그대로 저장되면 정상 코멘트가 지워졌습니다. 오류 문구(⚠️로 시작)는 저장하지 않고 이전 코멘트를 유지하도록 했고, 1시간 갱신은 코멘트를 건드리지 않도록 분리했습니다.

**실행 실패 인지**
자동화 특성상 오류가 나도 알아채기 어려워, 매크로 대시보드와 신용잔고 브리핑은 실행이 실패하면 텔레그램으로 실패 알림이 오도록 설정했습니다. 1시간마다 도는 노션 갱신은 알림이 너무 잦아지므로 알림 없이 다음 실행에서 다시 시도합니다.

## 파일 구조

```
.github/workflows/   스케줄 실행 설정 (브리핑 3종, 노션 갱신 2종)
dashboard.py         글로벌 매크로 대시보드 (텔레그램 + 노션 시장 지표 저장)
credit_balance.py    신용잔고 추이 차트
investor_flow.py     투자자별 누적 순매수 차트
kr_calendar.py       한국 영업일 판단 (주말, 공휴일, 연말 휴장일)
news_calendar.py     대시보드의 핵심 이슈 헤드라인, 미국 주요 일정
notion_market.py     노션 「📈 시장 지표」 DB 저장 (지표별 덮어쓰기)
market_hourly.py     시장 지표 1시간 갱신 (텔레그램·AI 없이 값만)
macro_monitor.py     노션 「🌐 매크로 모니터」 DB 1시간 갱신 (표준 라이브러리만 사용)
data/                수급 데이터 누적 저장
requirements.txt     공통 의존성 (차트·KRX·Playwright는 각 워크플로에서 추가 설치)
```
